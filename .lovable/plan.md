
# NST Venture OS — Build Plan

A new module mounted under `/os/*`. Existing routes (`/dashboard`, `/founders`, `/admin`, `/guide`) stay untouched.

## Access Model

- Only emails already in `profiles` (i.e. seeded by the import) can sign in. New `@newtonschool.co` signups are still allowed for staff; students need a `founder_id` linked to their profile.
- **Student**: sees only their own startup workspace at `/os`. Cannot list other startups.
- **Faculty / Super-admin / Leadership**: sees all startups, faculty review panel, leadership dashboard.
- `Nitish` + a new `leadership` role get the hidden Leadership dashboard.

## Routes

```text
/os                          → role-aware home (student → own workspace, staff → cohort overview)
/os/workspace/$startupId     → Startup Workspace (Overview, Progress, Monthly, Evidence, KPIs, Mentor, Reviews, Final)
/os/submit/monthly           → student monthly submission
/os/submit/weekly            → student weekly tracker
/os/evidence/upload          → evidence vault upload
/os/review                   → faculty review queue
/os/review/$submissionId     → AI summary + scoring panel
/os/mentors                  → mentor directory (staff)
/os/events                   → event participation (staff edit, students view own)
/os/simulations              → simulation scores
/os/committees               → review committee scores
/os/leadership               → hidden leadership dashboard (Nitish/Leadership only)
/os/founder/$founderId/career → career outcome recommendation
```

A new sidebar entry "Venture OS" appears for everyone signed in; the layout (`/os` route) handles role-based redirects so students land on their workspace.

## Database Additions

All new tables in `public`, RLS on, GRANTs explicit. No existing table is altered destructively.

- **startup_stages** (enum): `idea, discovery, validation, mvp, pilot, revenue, growth, fundraising`
- **startup_status** (enum): `active, paused, pivoted, merged, acquired, closed`
- **founders**: add `lifecycle_stage` (uses new enum), `lifecycle_status`, `mentor_id`, `next_review_date`. Existing `stage` text column kept for backward compat; new UI writes to `lifecycle_stage`.
- **profiles**: add `founder_id` (FK to founders) so a student's login maps to one startup.
- **weekly_trackers** — week_start, hours_worked, meetings, customers_spoken, features_shipped, revenue, users_acquired, experiments, failures, learning, roadblocks, support_needed
- **evidence_items** — founder_id, category (customer/product/business/behavior), kind (file|link), title, url, file_path, mime, size, month, week, notes
- **submission_packets** — founder_id, month, summary, what_worked, what_failed, what_changed, assumptions_invalidated, next_steps, submitted_at, locked
- **ai_evaluations** — packet_id, strengths, weaknesses, risks, missing, suggested_total, suggested_status, faculty_summary, raw_json, generated_at
- **faculty_reviews** — packet_id, reviewer_id, execution, customer, business, behavior, total, status, decision (approve|reject|edit|resubmit), comments, decided_at
- **committee_scores** — founder_id, level (founder_self|ai|faculty|mentor|board), reviewer_name, organisation, score, notes, month
- **events** — name, date, description; **event_participations** — event_id, founder_id, role (attendee|presenter|winner|volunteer), evidence_url, faculty_approved
- **mentors** — name, domain, email, availability, rating; **mentor_assignments** already exists, extended with notes + meetings_count
- **simulations** — name, founder_id, score, rank, status, faculty_comments, evidence_url
- **kpi_snapshots** — founder_id, month, interviews, features_shipped, mvp_velocity, revenue_growth, partnerships, experiments, consistency, mentor_engagement, evidence_completeness, timeliness (auto-calculated nightly + on submission)
- **academic_credits** — founder_id, subject (subject_1|subject_2), semester, monthly_scores jsonb, semester_score, final_score, pass, board_status
- **academic_alerts** — founder_id, kind (faculty_review|board_review), reason, status (open|closed), opened_at, closed_at — generated by trigger on 2 consecutive yellow/red faculty_reviews
- **career_recommendations** — founder_id, primary_path, alt_paths jsonb, rationale, generated_at
- **app_roles**: add `leadership` to existing `app_role` enum

### RLS Pattern

- Students: `EXISTS(SELECT 1 FROM profiles WHERE id=auth.uid() AND founder_id = <table>.founder_id)`
- Staff: `is_staff(auth.uid())` for read, `is_admin(auth.uid())` for writes on academic_credits/career_recommendations/committee_scores
- Leadership dashboard: `is_admin(auth.uid()) OR has_role(auth.uid(),'leadership')`

## Storage

A private bucket `evidence` for uploaded files. Path: `{founder_id}/{month}/{uuid}-{filename}`. RLS: students read/write own folder; staff read all.

## AI Evaluation

Server function `evaluateSubmissionPacket(packetId)` using Lovable AI (`google/gemini-3-flash-preview`):
- Pulls packet + evidence + KPI snapshot
- Structured-output JSON: strengths, weaknesses, risks, missing, suggested scores per pillar + total, suggested status, faculty_summary
- Writes to `ai_evaluations`. Scores stay hidden from students until a `faculty_reviews` row with `decision='approve'` exists.

KPI snapshot recomputation also runs server-side after each submission/evidence upload.

## UI / UX

Reuses existing `AppShell`, design tokens, `StatusBadge`, fonts. New module gets a tinted top banner so faculty know "Venture OS context". Components built with existing shadcn primitives.

Founder workspace layout:

```text
┌─ Overview ──────────────────────────────────────────┐
│  Startup • Team • Mentor • Stage(editable) • Next   │
│  Traffic light • Credits • Latest faculty feedback  │
├─ Progress (6-month timeline) ───────────────────────┤
├─ Tabs: Monthly | Weekly | Evidence | KPIs | Reviews│
│        | Mentor | Events | Simulations | Final     │
└─────────────────────────────────────────────────────┘
```

## Stage edit on founders page

Add an inline `Select` on the existing `/founders/$id` detail page that lets the founder (or staff) change `lifecycle_stage`. Writes go through RLS so students can only edit their own.

## Build Order

1. Migration: enums, new tables, RLS, GRANTs, triggers (academic_alerts, KPI on submission), storage bucket + policies, role addition.
2. Server functions: `submitMonthlyPacket`, `submitWeeklyTracker`, `uploadEvidence`, `recomputeKpis`, `evaluateSubmissionPacket`, `recordFacultyReview`, `recomputeCredits`, `generateCareerRecommendation`.
3. `/os` shell + role-aware routing, sidebar entry "Venture OS".
4. Founder workspace tabs (Overview, Monthly, Weekly, Evidence, KPIs, Reviews, Mentor, Events, Simulations, Final).
5. Faculty review queue + scoring panel with AI summary side-by-side.
6. Mentor directory, Event participation, Simulation, Committee score tables.
7. Leadership dashboard with cohort metrics + campus comparison.
8. Career recommendation page.
9. Stage edit control on existing founders page.
10. Audit-log every write through the existing `import_audit_log` table (extended `record_type` values).

## Out of scope for this build (call out)

- Email/push notifications — alerts are visible in-app only.
- PDF report generation (CSV/Excel for now; PDF noted as future).
- External mentor signup flow — mentors are seeded by admin.
- AI auto-recommendation of career paths is heuristic from scores/KPIs; can be upgraded to LLM later.
